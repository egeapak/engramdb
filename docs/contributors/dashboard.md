# The dashboard crate

This page describes `crates/engram-dashboard/` (`engramdb dashboard`) for contributors. The rules that prevent known defects, each with its guard test, are also listed in [`.claude/CLAUDE.md`](../../.claude/CLAUDE.md); read this page in full before you change the crate. The user guide is [../users/dashboard.md](../users/dashboard.md); budgets and measurements are in [dashboard-performance.md](./dashboard-performance.md).


## How paths are written here

Paths are relative to `crates/engram-dashboard/` unless they start with `crates/`, `src/ops`, `docs/` or `examples/` (those are relative to the repository root). The text was moved from `.claude/CLAUDE.md` word for word, so many paths are short. Read a short path this way:

- A Rust file name alone (`graph.rs`, `security.rs`, `writes.rs`) is in `src/`. `layout/mod.rs` is `src/layout/mod.rs`.
- A JavaScript module path that does not start with `web/` is under `web/js/`: `dom.js`, `api.js`, `views/graph.js`, `graph/details.js`. Paths that start with `canvas/` or `themes/`, and the names `strings.js`, `layouts.js`, `input.js`, are under `web/js/graph/`. A style's own file (`canvas.js`, `regions.js`, `relations.js` when the text is about Plain, `glyphs.js` when it is about Grid) is in that style's folder, `web/js/graph/themes/<id>/`. The core relation vocabulary is `web/js/relations.js`. `review.js` is `web/js/views/review.js`.
- A CSS path that does not start with `web/` is under `web/css/` (`plain.css` is `web/css/themes/plain.css`).
- `checks.mjs` is `bench/browser/checks.mjs`.
- `layout.js` names the page's former layout module, which no longer exists.

## Overview and process model

**`crates/engram-dashboard/`** (crate `engram-dashboard`, lib `engram_dashboard`) — `engramdb dashboard`, a read-only (bar the opt-in edge review below) web view of **every** store on the machine (registry projects with parent/child and worktree links, groups, global), with the start directory's project selected. **Its own process, never the daemon** (a TCP listener there would widen a 0700-socket model host and tie its lifetime to a tab); it loads no model, and semantic search is deferred. axum (`tokio`, `http1` only — no `json`/`query` features, which would pull `serde_path_to_error`; `api::json_response` and `form_urlencoded` replace them), `getrandom` for the token.

## Security model

**Security** (`security.rs`, one `guard` + one `headers` middleware, each check tested in `src/tests.rs`): 127.0.0.1 by default (`--bind` elsewhere warns); a random 32-byte token per run, handed over in the URL **fragment** (`/#token=…`: never sent to a server, never in a `Referer`), moved by `api.js::takeToken` into `sessionStorage` and stripped with `history.replaceState`, then sent as `Authorization: Bearer` on every `/api` call — the **only** accepted carrier. **No cookie, no `?token=`**: cookies are shared by every port on 127.0.0.1 (another local server would receive it, or plant a shadowing one), and a query string lands in history and logs. The static files are served **without** auth (they hold no data and the page must load before it can read the fragment); every byte of store data is behind `/api`. The browser is opened through `LaunchPage` — a 0600 `open.html` in a 0700 temp dir with a meta refresh, deleted when the guard drops at exit — never with the token in argv (`/proc/<pid>/cmdline` is world-readable). The token URL reaches the terminal **only** with `--no-open` (or, the one declared exception in `crates/engram-cli/src/commands/dashboard.rs`, when `open_browser` returns `None` — the launch file or opener failed — since the token is otherwise unrecoverable); a launched run prints the bare address (`address_url`), and JSON carries `url` under the same rule; `Host` must be `localhost`/a loopback IP/the `--bind` IP with the bound port (DNS rebinding — a bound `0.0.0.0` accepts any IP *literal*, never a name); any non-GET needs `Origin == http://<Host>` **and** `X-EngramDB-CSRF` (from `/api/session`); CSP `'self'` with no `unsafe-inline` (so no inline `<script>`/`<style>`/`style=` anywhere: dynamic colour goes through classes, `el.style.x` CSSOM writes are fine), `X-Frame-Options: DENY`, `no-referrer`, `nosniff`, `no-store` on everything but the ETag'd assets.

## Read path and stores

**No writes on GET**: stores open through `MemoryStore::open_read_only` / `open_global_read_only` / `open_group_read_only` (no `.gitignore` backfill, no dir/table/lock creation via `LanceIndex::open_existing`, no migration — `schema_state()` *reports* a stale schema) and sit behind `stores::ReadStore`, whose `MemoryStore` is private and which exposes reads only, in an 8-entry LRU keyed by location (failures never cached). It records **no usage event**: a page view is not a `fetched`, and counting it would let browsing feed promotion.

## The layout cache, the one write outside stores

**The one declared write outside stores** is the server-side layout cache (below): `<dirs::cache_dir()>/engramdb/dashboard/layouts/<digest>.json` (`paths::dashboard_layout_cache_dir`, overridden by `ENGRAMDB_DASHBOARD_CACHE_DIR`, which the `#[ctor]` test arm points at a temp dir; `ENGRAMDB_DASHBOARD_LAYOUT_CACHE=0` turns it off), never under a store, `.engramdb/` or the data dir; `the_server_layout_fits_the_response_and_is_cached_outside_the_store` pins that.

## Projects list and probes

`/api/projects` is built from the registry + manifests without opening any store, every probe on the blocking pool under `projects::ROW_TIMEOUT` (a hung mount is a "timed out" row, not a stalled worker) through `projects::off_runtime` — at most one probe in flight per key (a path, a far store, a store open) and a key that timed out refused for `PROBE_RETRY_AFTER` (30 s) without a new thread, so reloads over a hung mount cannot fill the blocking pool; `ReadStore`'s open, `doctor`, staleness and checkout-conflict reads go through it too — and keyed by the id **computed from the path now** (as `open_read_only` keys it), with the registry id kept as the row's API id; `/stats` probes only its own row (`projects::view`). The usage readers in `telemetry::usage` read the JSONL log through `spawn_blocking` for the same reason. A gone path or a store-less sub-project is a row with `unavailable_reason`, and a project route to one is a 409 (unknown id 404). `ReadStore` maps every failed *index* read: a store whose schema is behind (the dashboard never migrates, so a pre-0.3.0 table lacks columns) is a 409 `schema_behind` naming `engramdb reindex`, an ambiguous id prefix a 400, anything else a 500 — storage types a LanceDB failure as `StorageError::Index` and an ambiguous prefix as `StorageError::AmbiguousId` (`Validation` is input problems only), so no front end matches on message text.

## Read signals

**Read signals are never summed here either**: `/stats` returns `last_7_days`/`previous_7_days` per signal, the overview tile shows three numbers and the charts are small multiples (one row per signal, own scale and 0 baseline).

## Scope colours and the memories list

**Scope colours are decided once, server-side**: `api::color_slots` ranks top scopes (`top_scope_of`, the first segment of the first logical scope) over the whole store (invalidated included) by count then name, and every endpoint (`top_scope` + `color_slot` on rows, nodes and attention items, `slot` on scope counts: `facets.scopes`, `by_scope`, `scopes`, `stub_scopes`) uses it; the frontend paints `slot % 7` and changes badge shape past seven. The memories list pages by a **keyset** cursor (sort key + id, bound to its sort), since usage sorts move with every read; its facets count what the status filter admits. "Current" is `detect_worktree_main(dir)` → `compute_project_id`, i.e. worktree routing without `resolve_project_root`'s side effects, which is why `Dashboard` is in `cli::run`'s exempt list (no maintenance pass either).

## Frontend

Frontend: `web/` (vanilla ES modules, no bundler/Node/CDN/web fonts), embedded by `build.rs` into an `(path, bytes, mime, etag)` table; `--assets-dir` serves from disk with `no-store` (canonicalized containment). Untrusted text goes through `dom.js`'s `h()`/text nodes and the DOM-building `markdown.js` subset — never `innerHTML`; `the_frontend_never_parses_html_or_inlines_script_or_style` and `every_import_resolves_to_an_embedded_file` guard both.

## Neutral wording

**Neutral wording** (graph view v1.1): the core frontend says graph / memory / relation / scope; transit-map words (station, metro, route map, connector, interchange, disruption, network, Night/Day map, "line" for a scope, the retired `line_*` API names, and bare `.line`/`.lines` property reads) are banned by `the_core_frontend_uses_neutral_words`, which scans every embedded asset (JS string literals via a small tokenizer, so `line-height`, SVG `<line>` and code identifiers do not trip it) and exempts only `web/js/graph/themes/grid/`, the one place flavour words may live (Plain and every new style are scanned like core). Both `/memories` and `/graph` filter top-level scopes with `top_scope=`; `scope=` exists only on `/memories`, as the older substring filter over every scope. Each name in `top_scope=` (a comma list) and in the Relations tab's `from_scope=`/`to_scope=`/`touches=` is percent-escaped (`api::scope_key(s)`, `scopes.js::scopeKey`): `-` is no scope, a scope named `-` is `%2D`, a comma `%2C`; a bad escape is a 400.

## Scope overview and drill-in

**Scope overview / drill-in**: above `OVERVIEW_MIN` (150, `views/graph-overview.js`) memories with no `top_scope=` and no `all=1`, the page asks `/graph?summary_over=150` (a store at or under 150 comes back whole and draws exactly as before) and renders the core overview: discs (the server's `scope-overview` layout, `src/layout/overview.rs`, pixel space, reusing scope-force's `pack`, same arithmetic rules), bands from the unfiltered pairs (display chips re-count through `graph/tally.js` and never move a disc), bands under max(2, 12% of the largest) dropped with a note, ⚠ always (a hairline when dropped), a pairs table. An opened scope (`top_scope=<one name>` in a store over OVERVIEW_MIN; a smaller store filters to the scope with the style's own layout, as before) is laid out by `scope-force` whatever the style, each node's group key its sub-scope (`layout::sub_key`, sent back per node as `group`); a style whose own layout is scope-force draws that as its backdrop, any other gets the core's neutral `drawRegions`; stubs run to one tag per far scope placed in its overview direction (`placeTags`, the directions sent with the layout as `dirs`), a tag opens that scope, a breadcrumb goes back. `all=1` (*Show all memories*) is the style's full graph, its back button in the tools row so the box does not move (Grid stays pixel-identical). On a graph of more than OVERVIEW_MIN memories at ≥ 3× Fit, `drawEdges` (and the tag stubs) draw only relations with both ends on screen whole (one end: a short `.cut` stub), recomputed when a view settles, never per frame. The UI says *relation* (never edge) and *type* for a memory's type (*kind* is a relation's only); API paths and JSON fields keep `edges`/`kind`.

## Graph API (`/graph`)

**Graph view** (`graph.rs`, `GET /api/projects/{id}/graph`): reads `ops::links::graph_of` (`load_graph` over the memory list it already read, so the memories table is read once), bounded (`limit`, default 800, max 2000, ranked degree → reads → criticality → id, `truncated` declared); `scopes` (per top scope: `count`, `slot`, `shown`, `subs` = per first-two-segment sub-scope counts) and `scope_edges` (per top-scope pair: symmetric kinds unordered `a ≤ b`, directed ordered, `a == b` = inside; `count`, `kinds: {kind: {status: n}}`, `contradictions`, `proposed`) are counted over **every** memory the status filters admit, before `top_scope=` and the limit, so the picker never shrinks and the overview is never the truncated part; with `top_scope=`, relations leaving the scope are `stubs` (per drawn memory × far top scope) and `stub_scopes` (per far scope, over the whole opened scope), and `counts.hidden` counts neither them (drawn end or not) nor relations with both ends outside; a dangling or cross-store relation has no far top scope, so it is in none of `scope_edges`/`stubs`/`stub_scopes` (only `counts.dangling`/`external`); `summary_over=N` answers a store of more than N admitted memories with the totals alone (`summary: true`, no nodes, edges or far-store probes); a far end in another store is probed with `open_store_by_id(.., read_only = true)` under `ROW_TIMEOUT` **per probe**, at most 8 stores, concurrently (`graph::probe_stores`, a `JoinSet` over `off_runtime` — serial probes made 8 hung mounts cost 8× the timeout), and an unprobed or timed-out one is `unknown`, never `dangling`; the memory page's relations (`ReadStore::links_of`) resolve far ends through the same prober rather than `ops::links::links_of`'s serial opens. The endpoint returns proposed edges by default and rejected ones only with `include_rejected=true` (default false); the page asks for both and filters kinds/proposed/rejected **client-side** over one laid-out edge set, so toggling them never moves a memory (only `invalidated` and `top_scope` refetch). Labels are cut from the summary (the index has no title column) and placed collision-free by `placeLabels` (`src/layout/labels.rs`, which every server layout calls; the page keeps `graph/labels.js::placeLabels` only for the focus-time `relabel`); one with no free spot comes back `placed: false` at a fallback position, drawn hidden (`.lbl.unplaced`) and shown only while highlighted — never overlapped.

## Graph styles

**Graph styles** (`web/js/graph/themes/<id>/index.js`, registry `themes/index.js`): `views/graph.js` is the core — data, filters + hash, selection/pin/hover, keyboard, details card, relations table, review/CSRF, counts, core strings (`graph/strings.js`, read through `t(key)`, the style's `strings` first) — and builds each node `<g>`/edge `<g>` (handlers, aria, focus ring, hit path) around what the style returns. A style exports, as named exports, `id` (= its folder), `name`, `strings`, `layout` (`{ name, options: {} }`: `name` is an own key of `graph/layouts.js`'s frozen `LAYOUTS` — `scope-force`, `grid` — every one computed by the server, which the page asks for with `layout=<name>`; a layout takes no options. `layouts.js` holds the output contract the decoded layout meets: `pos`, `routes[k]` for every edge incl. stubs (≥ 2 points), `labels[i]` always `{x, y, anchor, placed}`, `bounds`, extra fields passed to `drawBackdrop`. Phase E's scope overview is a separate core render path the server lays out, not a style hook), `drawBackdrop`, `drawNode`, `drawEdge`, `edgeSample`, `legend` (`every_graph_style_exports_the_interface`: named exports, none `undefined`/`null`, `id` = folder, `layout.name` in `LAYOUTS`, listed in `STYLES`); its CSS is `css/themes/<id>.css`, linked from index.html, every rule under `[data-graph-style="<id>"]` (set on `<html>`; `data-theme` is light/dark; `every_graph_style_css_is_linked_and_scoped`). Core CSS draws only the focus ring and the relation click target (`.cx .hit`); highlighting is classes only that each style's CSS interprets, faded look included: `.has-focus` on the `<svg>` (one class does the global fade — never iterate every memory per hover), `.on` on the focused memory, its relations, stubs and neighbours, `.nb` on the neighbours (and their labels, so a `placed: false` label shows), all set from `drawEdges`' adjacency. **No opacity transition** on memories/relations (it re-layerized all of them each hover frame: 15.8 → 9.2 ms p50 at 800), and a hover's leave is applied a frame later and cancelled by the next enter (toggling `.has-focus` off and on in one task cost an ~8 ms invalidation walk); the tooltip is measured in the next frame.

## Details panel

**Details panel** (`graph/details.js`, core): a selected memory's panel replaces the card — summary, type, scope, criticality, status, reads, then relations in words from the selected memory's side, groups in `PANEL_GROUPS` order (contradictions first; `Supports`/`Supported by`, `Supersedes`/`Superseded by`, `Derived from`/`Source of`, duplicates, related; unknown kinds by name via `relOther`; `the_details_panel_words_every_relation_kind`), rows naming the other memory (a button that selects it), its scope or *same scope*, Proposed/Rejected, a dangling/not-checked note; an opened scope's stubs are per-far-scope rows (tallies carry no direction) that open the scope. Proposed rows carry `reviewControls(..., {viewer})`, **not rendered at all** when read-only (one note instead); a pinned relation's card and the memory page keep theirs (disabled + note) — the relations table still pins edges there until phase G. With a memory selected, `]`/`[` step the panel rows (focusing the neighbour quietly, so the selection's highlight stays; on a stacked layout focus stays on the row and the neighbour gets `.cur`; every row's words go to a live region, since a node's own label has no direction), Enter selects / opens, Escape clears and refocuses the graph in one press. A focus re-runs `placeLabels` over the lit subset only (`relabel`, O(degree)) so revealed labels never overlap (no spot → `.nolbl`, named in the tooltip, which sits in the corner away from the memory). After a review the reload selects the first of `afterReview(ids)` still drawn (a superseded loser is hidden by default, so the other end takes over) and re-inserts the result empty-then-filled so it is announced. `review.js` keeps a watcher set per edge key: when a review settles every live box for that edge re-renders, so a panel rebuilt mid-send never sticks at "Saving…". The legend's structure and words are core (`graph/legend.js::buildLegend`), its swatches the style's (`scopeSample`/`nodeSample`/`edgeSample`/`stubSample`, plus `direction`). The pick: graph hash `style=`, else localStorage `engramdb.graphStyle` (try/catch), else `DEFAULT_STYLE` (`'plain'`); the toolbar *Style* select writes both (and keeps focus, via `ctx.navigate(hash, {keepFocus})`); non-graph views fall back to the stored pick; other pages' relation samples follow the picked style, but a style's flavour strings reach the header's light/dark label only on the graph view.

## Grid

**Grid** (`themes/grid/`: its layout is the server's `src/layout/grid.rs`, seeded — mulberry32 from a 32-bit FNV of the ids — so a store always draws the same graph, ported bit for bit from the former `layout.js` (V8's `Math.hypot` algorithm and `cos`/`sin` bits as constants) and screenshot-diffed at 0 % when the JS was deleted; `glyphs.js`; the backdrop reads the layout's `chains`) is the original look and the only folder the neutral-wording scan skips, so it alone keeps flavour words ("Night map"/"Day map", "<project> network").

## Plain

**Plain** (the default) is laid out by the server's `scope-force` (`src/layout/scope_force.rs`; core, not Plain's, because it is no look and phase E's opened scope needs it too): scope discs packed by cross-scope relation counts as the start, then a simulation with spatial-grid repulsion cut off at 6 spacings (exact within 3 × 3 cells, per-cell centres of mass beyond), relation springs, a pull to the top-/sub-scope centres weighted by how many of that scope's relations stay inside it, weak aspect gravity; overlap removal; small graphs spread toward `SPREAD_TO` so Fit is ≈1:1; scope names as `placeLabels` obstacles at a width-free size, with the opt-in `corners` and `nudge` (≤ `NUDGE_MAX` memories; `nudgeTest`: ≤ 1.5 spacings, never nearer another scope's centre, no added crossing, spatial-grid segment tests on a `NUDGE_WORK` budget, hubs over `NUDGE_DEGREE` never move), then the names re-placed at the drawn size (`scopes`, sized by `input.width`, the box's px width — the **only** output that depends on it; positions depend on nodes, edges and aspect only, so the cache keeps the width-free core and Grid's key never sees the width); straight routes, stubs toward their far scope else away from neighbours. **Determinism**: no random numbers, id-ordered loops, maps in insertion order, and only `+ − × ÷ sqrt` in positions (angles are literals). Its backdrop is one region path per scope (each disc at least the memory's own radius + 6, from the core `graph/radius.js` the view draws nodes with) + one name each (a faint backing box when the name covers memories, `backed`); memories are one neutral fill (colour is the relations'; never-read ones hollow), and regions past the seventh scope add a texture (slots 7–13 hatch, 14–20 dots, 21–27 cross-hatch), so within 28 scopes a repeated tint never repeats a texture; past that only the names tell them apart.

## Plain's relations

**Plain's relations** (`themes/plain/relations.js`; imports nothing from `themes/grid/`, `plain_draws_relations_without_grid_glyphs`) have no arrowheads: direction is a filled taper, wide (≈ 3.3×) at the source; kind is colour **and** shape (contradicts red zigzag, duplicates violet double, supports green wedge, derived_from blue comb — a solid core with ribs, never reading as dashed — supersedes heaviest wedge in the text colour, related_to thin grey; proposed = dashed + one mid chevron on directed kinds, and a confirmed directed one shorter than `SHORT_PX` (40) on screen gets the chevron too; rejected faint dotted; stubs fade through one of two shared masks, and only `state: dangling` ends in a bar and fades less — a live cross-store far end is not "deleted", in Grid too, which now caps only dangling/unknown), colour tokens in `plain.css` in app.css's three-block pattern (`body:is(:root:not([data-theme=light]) *)` keeps the scope prefix), checked ≥ 3:1 on both backgrounds with the exceptions declared there. `DIRECTED` (core `relations.js`) has a null prototype and `isDirected` uses `Object.hasOwn`, since a kind is any string (`constructor` must not read as directed).

## Drawing a relation

**One `<path>` per relation**, all subpaths of one `relationPath(kind, status, L, k)` in a local frame, placed by a CSSOM `transform: translate rotate scale(1/UNIT, 1/UNIT × var(--zw) × var(--zk))`: the core calls the optional style hook `zoomed(svg, scale)` from `apply()`, which writes `--zw` on the `<svg>` only when it moved 2 %, so a zoom rescales every width with no per-relation JS (widths go as scale^0.4 on screen; along-relation lengths are sized at draw time from `ends.scale`), and a second optional hook `redrawOnZoom(drawnScale, scale)` lets the core redraw just the relations 160 ms after a zoom settles, when the along-relation unit moved more than `REDRAW_RATIO` (1.5×) — never per frame; `.on` sets `--zk: 1.5`. Path building is linear and bounded: knots and ribs by index per dash interval, and the unit raised so no relation carries more than `MAX_DETAIL_PX` (180 px) of along-relation detail; `d` is written in integers of 1/`UNIT` (20) px, scaled back by the transform, because formatting decimals dominated a zoomed-in build (`node bench/relations.mjs` asserts no NaN, wide end at the source, chevron direction, bounded `d` length, own-key kinds, and times 2k relations at Fit and max zoom). `edgeSample`/`stubSample`/the graph all call `relationPath` (`plain_legend_swatches_share_the_relation_drawing`), and the legend's direction sentence (`legendDirection`) is core wording shown only when a style passes `direction: true` to `buildLegend`, so Grid's legend is unchanged. `placeLabels`' options are off by default, so Grid places exactly as before.

## Surfaces (SVG and canvas)

**Surfaces** (`graph/surface-svg.js`, `graph/canvas/host.js`): the core view draws through one surface interface (`el`, `pointerEl`, `composited`, `nodeIndexOf`, `focusNode`, `setHub`, `setCur`, `resetEdges`, `edge`, `placeEdges`, `setStubs`, `setTags`, `show`, `settled`, `gesture`, `highlight(plan)`, `flush`; listed in surface-svg.js) and names no style. The SVG surface is the DOM described above (Grid, the fallback when there is no 2D context, and a non-canvas style's opened scope); the **canvas surface** is picked by a style exporting `renderer = 'canvas'` plus a frozen `canvas` hook object from its own `canvas.js` (`look`, `tokens`, `backdrop`, `drawBelow`, `drawAbove`, `edge`, `drawEdges`, `drawNodes`, and the optional `edgeRank`; `a_canvas_style_exports_every_canvas_hook` also checks every `hooks.<name>` host.js and scene.js call is listed, the optional one guarded at its call, and every `look` field the core reads — `fadeNode`/`fadeEdge`/`fadeLabel`, the optional `fadeBackdrop`, `hitWidth`, `labelWeight` — is in the style's `look`). The core holds no style's fields: faded relations go through the `edges` part at the group opacity `look.fadeEdge`, a lit relation is `drawEdges(.., { lit: true })` and the style picks its width (Plain: `look.litWidth`), and the backdrop fades as a group at `look.fadeBackdrop` (Plain: 1). Plain is the only canvas style; Grid stays SVG and pixel-identical (screenshot-diffed at 0 %); the scope overview and legend swatches stay SVG. The host owns everything a second canvas style would reuse; what it shows is a function of plain data (`canvas/scene.js`: the scene and every part's and layer's drawing; it reads no page state, and the only canvas it makes is an off-page one for measuring label text — a style's hooks may make their own, as Plain's textures do). At most **two canvases in the page at once** (in software compositing every visible canvas re-sends its whole backing store on each changed frame): an opaque base, or with a focus or hover an opaque faded copy `dim` in its place, plus a small **patch** canvas over the lit bounds only, snapped to whole CSS pixels (a half-pixel one is resampled by the compositor and no longer matches the layer it is flattened into mid-gesture) (its underlay a copy of the shown layer, with a focus the lit memories' label boxes redrawn without their faded labels (`labelHoles`), then the lit subset, marked tags and rings; hidden when empty; tags are in both layers unfaded, so only a marked one widens it). **Three off-page part bitmaps** (`scene.js::PARTS`, each with its own version and frame key): `below` (opaque backdrop), `over` (above + labels + memories, unfaded) and `faint` (labels and memories, each faded as a group, `drawFaint`); relations, stubs and tags (what a filter changes) are in no part. The base is `below` + stubs and relations drawn straight in + `over` + tags; `dim` is `below` + the relations as a group at `look.fadeEdge` (through a rect-sized scratch canvas, dropped after use) + above + `faint` (so a filter under a hover costs the relations and three blits: the faint part took the s2k hover-toggle 68 → 32 ms at DPR 2); where a part is behind, a layer draws from the scene (`drawUnfaded` / `drawFaded`). Five full-size canvases in all, capped at `LAYER_PX` (3 M device px) each with the margin, so a DPR 2 box gets a narrower margin (canvas MB at DPR 2: 114–122 → ~58; the budget is ≤ 60). **Every layer and part keeps `pend`**, the device rectangles it owes for its (version, frame): `bring` moves one to a frame (a whole-device-pixel pan at the same version copies its pixels, shifts what it owed and owes the uncovered strips — each strip under its own rectangle clip, an even-odd clip of both cost 90 ms a pan at DPR 2 — else it owes everything), `settle(ly, region)` draws what it owes inside a region in one pass under a union clip. A flush settles only the shown layer's **box**; the margin (in the frame from the first drawing on), the parts (first, so a toggle or hover meanwhile finds them current) and the hidden layer are drawn by an idle **pump**: bands sized from each kind's measured ms per pixel with a 1.5× safety factor, none started with under `STEP_MS` left, at most `ROOM_MS` (30) per callback, each forced to raster through a 1 × 1 sink (`rasterNow`: a canvas records until something needs its pixels); a kind's first band (its backing store's allocation, ~30 ms at ÷4 whatever the size) is the smallest and runs alone. Headless software compositing grants **no idle period** while nothing changes on screen, so an idle callback ran only at its timeout (the pump took 1.5–6 s to finish); one that times out switches the rest to `scheduler.postTask` background tasks of one step each (`bgCall`), until nothing is owed. A filter's changed memory looks (`setHub`) are owed as their discs (`nodeReach`) a double rAF later (one rAF landed in the measured frame), drawn in `few` mode (only the labels and memories that reach the rects); plain/canvas.js keys relation groups by kind × {rejected, proposed, neither} and caches each group's Path2D by record identity (`lastGroup`), so a filter rebuilds no path (`edgeRank` matches that order). `show()` snaps a pan to whole device pixels. A drawing built from copies and rectangles is within antialiasing of one drawn whole, not bit-exact (Skia antialiases a path the canvas edge or a rect clip cuts by another route): `checks.mjs` waits for `graphDebug.idle()` and bounds the filters / theme undo at < 0.05 % of pixels against a whole drawing (`graphDebug.redrawAll`). Mid-gesture `surface.gesture(true)` draws the patch into the layer under it so one canvas moves. The accessible list is clipped from paint (`.g-a11y:not(:focus-within), .g-pane.zooming .g-a11y { contain: paint }`): its 800 positioned buttons made every hover frame re-layerize the page (15 → 8.6 ms hover at DPR 2) and every zoom frame with the box focused (16 → 54 fps at DPR 2, CPU ÷4); a focused button is unclipped so a screen magnifier can follow it. **The first paint is the graph alone**: the accessible list (`makeButtons` in idle slices, finished by `ensureList` when the view moves focus to a memory, so keyboard input always finds it), the legend and the relations table are built after it through `dom.js::afterPaint` (two frames, then idle — one frame let idle work land before the paint), the relations table's rows after the first `TABLE_SLICE` (10) follow in later idle slices (a page of them was a long task at ÷4), and the first drawing settles only the box (its margin owed to idle time). A worker raster (OffscreenCanvas) was built and measured slower (53 → 96 ms first paint) — don't reintroduce it without new numbers (docs/contributors/dashboard-performance.md, "Draw time against the spike") — an overscan margin (12 % of the box's larger side), devicePixelRatio capped at 2 and 6 M device px, CPU hit testing on uniform grids (`canvas/hit.js`: memory over relation; among relations the one drawn on top, by the style's optional `edgeRank` hook then index, so a hit matches the draw order; a relation within `look.hitWidth`; the box's CSS size from `boxSize` against the drawn view, so a height-only resize keeps hits right), the accessible list (an `opacity: 0` button per memory, named by `graph/a11y.js::nodeAria` like the SVG `<g>`, placed by one matrix per view, built by `makeButtons` in idle slices of `LIST_SLICE` after the first paint and finished at once by `ensureList` when the view moves focus to a memory; the focus ring is drawn on the canvas; the picture's `role=img` and label sit on `.g-cv-pic`, an element that is never hidden (the canvases take turns), the label counting the relations the filters leave; `the_canvas_accessible_list_covers_every_memory`), the device ratio watched by a `matchMedia` resolution listener re-armed on each change, tokens read with `getComputedStyle` once per light/dark or style switch (a MutationObserver on `data-theme`/`data-graph-style` + the media query), and the gesture rules: a canvas pan is a composited gesture too, and the settle redraws synchronously in `apply()` (no second 160 ms timer). `show` repeats the SVG's view-box arithmetic (0.1-unit rounding, meet, centred) so both surfaces put a memory on the same pixel. Plain fills relations in batches (one Path2D per kind × rejected, each relation written straight into it through a placed sink by `relationShape` — `relationPath`'s geometry with a pluggable sink and a fast path for solid bands — reused until the width factor moves 2 %; **no `closePath`** in those paths: Chrome's costs time in proportion to the path so far, which made a group's closes quadratic; the drawing is run once over made-up relations while the page is idle, `warmStep`, so the first graph finds it optimised; regions are built with `arc` from `regions.js::regionDiscs`, the same discs the SVG's `regionArcs` writes), so where two kinds cross the stacking is by kind (faint first), not index — a declared difference from SVG; memories one Path2D per look. `bench/browser/checks.mjs` checks both surfaces (accessible list, keyboard, hover hit, click, relation pin, filters, zoom settle, theme switch, console, same labels as SVG); `bench/browser/views.mjs` times them (first paint, settle, zoom/pan fps, hover frame, heap/DOM).

## Server-side layout and cache

**Server-side layout** (`src/layout/`) is the **only** source of every layout — scope-force, `grid`, the scope overview; the page has no layout code (no worker, no fallback; only the focus-time `relabel`), and `the_server_layouts_have_no_browser_copy` checks no layout module or `new Worker(` is embedded. The layouts began as statement-for-statement ports of the page's JS and keep its arithmetic rules (`js_round` for `Math.round`, `js_cmp` = UTF-16 order, UTF-16 text lengths, maps in insertion order, numeric map keys as the same doubles via `fkey`); there is no JS to match any more, so the guards are Rust property tests in `src/layout/tests.rs` — output contract (finite, routes from their memories, placed labels never overlapping, everything inside the bounds), determinism (same input, same bytes, also through the cache's binary form), overview discs never overlapping (≤ `PACK_MAX` scopes), a non-finite layout is an error — on generated graphs and the three `/graph`-shaped inputs in `src/layout/fixtures/`. **Any change to a layout's output must bump `LAYOUT_VERSION`** (the cache key's salt). The page measures its box before fetching (`views/graph.js::measureBox`: a hidden zero-height `.g-probe` copy of the grid, with the root's `overflow-y` forced to what the drawn page will need, so a scrollbar that only the graph brings is already counted) and asks `/graph?layout=scope-overview,<the style's layout>[,opened]&layout_aspect=&layout_width=[&layout_open_over=150]` (`opened` for one scope, which the server groups by sub-scope only when the store holds more than `layout_open_over` memories — a smaller store's scope is a plain filter with the style's own layout). Aspect must be a whole multiple of 0.05 and width of 40 from 40 up to 20 000, else 400 (`input.js::roundAspect`/`roundWidth`, which clamps to [40, `MAX_LAYOUT_WIDTH`] so an ultrawide box never turns the whole `/graph` into a 400, and sends `DEFAULT_LAYOUT_WIDTH` (800) / aspect 0.6 for a box that was not measured). The server builds the input from its own response (`layout::build_force_input`/`build_overview_input`) and runs it on the blocking pool — **single-flight per key, at most 2 computing (`cache::MAX_COMPUTING`) and 16 queued (`MAX_QUEUED`)**, no timeout: a request waits for its layout; one beyond the queue is a 503 `layout_busy` with `Retry-After: 1`, which the page retries (1, 2, 3, 5 s, saying it is laying out) before an error with *Try again*; a failed layout (non-finite, a panic) is a 500 `layout_failed`, never cached, shown with *Try again* — and splices the encoded JSON **text** into the response (serde_json without `float_roundtrip` does not parse every double back exactly). scope-force's cached result is the **width-free** core (`ForceCore`); `scope_force::finish` places the scope names for the asked width per request, so one cache entry serves every box width; an opened scope's tag directions (`dirs`) come from the cached overview of the same box. Encoding `v` 4, keyed by the response's own `nodes`/`edges` order (no input checksum — it rides in the same document; contract in `layout/mod.rs` and `graph/server-layout.js` docs): positions, label positions and routes as LE `f64` base64, `label_flags` one byte per label (anchor index | 0x80 placed), `group_keys` + per-node `group`, the rest JSON; Grid's routes in edge order with `route_points` (a count byte per edge) and `chains` (per scope `{key, slot, pts}`); the overview as plain JSON with `ids` and `pairs` (scope names) the page matches by name (`decodeForce`/`decodeGrid`/`decodeOverview` throw on anything malformed). `--assets-dir` gets the server layout like embedded assets. Cache (`layout::cache`): 32 in memory + ≤ 64 MiB on disk, keyed by the SHA-256 of `LAYOUT_VERSION` + `CARGO_PKG_VERSION` + name + the exact input, binary `<key>.bin` files (magic `EDL2`, version, key, payload, then a SHA-256 of all of it; a file failing it, or a scope-force core with a non-finite number (`ForceCore::is_finite`, checked on a fresh layout and on a read), is a miss and recomputed, and a core that does not fit the request's graph is refused at render and `LayoutCache::forget`ten); 0700 dir refused if group/other bits or another owner; files opened once with `O_NOFOLLOW|O_NONBLOCK`, checked regular and size-capped on the handle, read and touched through it; 0600 writes via temp + rename, mtime LRU that deletes only the cache's own names (`<64 hex>.bin|.json`, `.<64 hex>.<n>.<n>.tmp`; the dir may be one the user pointed it at), corrupt/foreign files ignored and replaced (an overview or grid whose text is not JSON included, since it is spliced in verbatim), loss paths declared in the module docs.

## Zoom gestures

**Zoom gestures** (wheel, pinch) move the drawn map as one composited layer (`gestureZoom`: a CSS transform on the `.g-pane` wrapper, never on the `<svg>`, which re-lays it out) and set the view box once the gesture settles (160 ms); hover is ignored mid-gesture (the map moving under a still pointer hovered a memory per frame). Measured 23 → 59 fps on the 10k opened scope at 4× CPU throttle (`run.mjs --cpu-throttle 4`). ## Relations tab

**Relations tab** (`relations.rs`, `GET /api/projects/{id}/relations`; `web/js/views/relations.js`): the same `graph_of` read (`ops::links::graph_of` is `load_graph` over rows the caller already listed, so `/graph` and `/relations` read the memories table once, not twice), one row per deduplicated relation (dangling ones included, `state` as on `/graph`, far stores probed **for the page's rows only**). Filters `kind=`/`status=` (repeatable or comma; default every status but `rejected` — `include_rejected=true` or `status=rejected|all` — so a newer binary's status is listed, not dropped), `q=` (both summaries, note, id prefix), `include_invalidated=`, `from_scope=`/`to_scope=` (exact; directed = source→target, symmetric either order), `touches=`, `subs=1` (sub-scope names for the pair *and* the matrix). Order proposed → contradicts → newest `at` → id; **keyset** cursor `{f: digest(Filter::canonical()), key}` (hex JSON, `api::hex_json`; a digest so `q=` ≤ 256 chars never outgrows `unhex_json`'s cap), ids/keys of a same-store symmetric relation from its sorted endpoints, and `edge_index::dedupe` breaks a same-status tie between a symmetric edge's two copies by owner id so the kept row does not follow scan order, a cursor sent with other filters is a 400 (`limit` is not a filter). `matrix` is first-page only and counts over every filter **but** the scope ones, a directed relation in its (src, dst) cell and a symmetric one in both, so a cell's count is what its click lists; far-scope-less relations are `unplaced`. The frontend keeps filters + picked cell in the hash, the matrix is one roving-tabindex stop, review uses `reviewControls` only with `--allow-writes` (read-only: one note), and a review reloads with the result named at the top. *Show in graph* links `graph?memory=<id>` (plus `top_scope=` above `OVERVIEW_MIN`); the graph view pins that memory once and drops `memory=` from the hash, or notes that it is not drawn. The graph's relations table links back (*Open in Relations*).

## The one write path

**The one write path** (`writes.rs`): `POST …/edges/confirm` and `…/edges/reject`, refused with 403 `read_only` unless `--allow-writes`, behind the guard's Origin + CSRF check, after an in-page confirm step (never `window.confirm`; `the_frontend_never_opens_a_browser_dialog`). Each request opens a **writable** store through the ordinary `MemoryStore::open`/`open_group`/`open_global` (never the read-only cache, which cannot write by construction), writes through `ops::links::{review_link, review_contradiction}` with `Surface::Dashboard`, then `StoreCache::invalidate`s the location — even on a refused write, since the open may have migrated the store. **A review requires the edge to still be `proposed`**, checked under the write lock: the same review again is a no-op (`changed: false`, 200), any other is `ops::links::NotProposed` → 409 `not_proposed`; a missing edge is `EdgeNotFound` → 404 `unknown_edge`; any other `StorageError` is a 500, never the caller's fault. Settling a same-store `contradicts` edge (both stand, supersede, reject) also resolves the NLI challenge on either memory that names the other (`resolve_nli_challenges`, matched by `nli::names_nli_contradiction_with` — the challenge evidence carries the other id for that), and the response lists them in `resolved_challenges`; the page also remembers a review per edge so a re-rendered control never sends twice. `supersedes` has no review (400; `unlink` it). Every GET stays side-effect free with writes enabled (`the_graph_and_detail_views_write_nothing`).
